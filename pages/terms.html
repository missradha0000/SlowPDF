Data Loss, Browser Limitations & User Backup Duty

Because all file parsing, splitting, merging, conversion, and rendering takes place directly inside your computer or smartphone's web browser memory (RAM), execution stability is governed strictly by your personal hardware, operating system, and browser engine.

MANDATORY USER BACKUP REQUIREMENT:

YOU MUST ALWAYS MAINTAIN AN ORIGINAL, UNMODIFIED BACKUP COPY OF YOUR DOCUMENT ON YOUR HARD DRIVE OR SECURE STORAGE PRIOR TO USING ANY SLOWPDF TOOL.

If your web browser crashes due to an out-of-memory error (e.g. attempting to rasterize a 500MB scan on a device with low RAM), if your battery dies, if an operating system freeze occurs, or if a corrupt PDF byte stream causes a download failure, THE RESPONSIBILITY LIES SOLELY AND EXCLUSIVELY WITH THE USER. SlowPDF and its creators accept ZERO legal, financial, or technical liability for lost, corrupted, damaged, or unrecoverable documents.

Technical Realities of In-Browser PDF Processing:

Users must understand the physical constraints of client-side JavaScript execution:

  • Standard mobile web browsers limit single-tab RAM usage to 1.5GB – 2GB. Attempting to merge dozens of high-DPI scans can trigger silent browser tab terminations.
  • Damaged, malformed, or proprietary non-standard PDF formats created by old printers may not deserialize correctly in open-source parsers.
  • SlowPDF cannot restore or undo an operation once a browser tab is closed because we hold zero file records.
